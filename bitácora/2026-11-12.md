## Resumen del Día

Puesta en producción completa de **Etronic (`https://etronic.com.mx/`)** sobre **cPanel (`finlexprimecom` / `mxmexsrv100.edr.com.mx`)** coexistiendo de forma aislada con otros dominios y aplicaciones Node.js del mismo servidor; creación e inicialización del esquema PostgreSQL (`finlexprimecom_etronic`) con acceso verificado al **Panel de Administración (`/adminetronic`)**; e implementación, validación y puesta en marcha del **despliegue continuo automático (CI/CD)** desde **GitHub Actions** hacia cPanel vía **HTTPS Puerto 443 (`deploy-hook.php`)** para Frontend y Backend.

## Implementaciones, Modificaciones y Cambios Realizados

### 1. Plan de Despliegue y Aislamiento Multi-Dominio en cPanel
- **Arquitectura de coexistencia segura (`Plan_Despliegue_cPanel_Etronic.pdf`):**
  - Se validó y documentó la separación por carpetas independientes en cPanel (*Document Root* propio para `etronic.com.mx`, *Application root* exclusivo en `backend_etronic` bajo Phusion Passenger en `/apietronic`, y base de datos dedicada `finlexprimecom_etronic`) sin interferir con otros dominios activos como `recuerdalo.com.mx`.
- **Corrección de cliente Axios local (`Frontend/src/api/axios.js`):**
  - Se eliminó una declaración duplicada de `defaultApiUrl`, dejando la resolución limpia hacia `"/apietronic"` en producción (`import.meta.env.PROD`) y `"http://localhost:3000/apietronic"` en desarrollo local.

### 2. Inicialización de Base de Datos PostgreSQL y Cuenta Administradora (`Backend/SQLscripts/`)
- **Scripts SQL de esquema e inyección inicial (`seed_etronic_postgresql.sql` y `seed_etronic_mysql.sql`):**
  - Se estructuraron las tablas `public.usuarios`, `public.chat_conversaciones` y `public.chat_mensajes` junto con la inserción `ON CONFLICT (correoregistro) DO UPDATE` de la cuenta administradora principal (`adminetronic27@gmail.com`) utilizando hash `bcrypt` y sin exponer contraseñas en texto plano.
  - Se solventó el bloqueo del WAF ModSecurity (`403.shtml` / `HTTP 401`) en phpPgAdmin ejecutando la carga del esquema sobre `finlexprimecom_etronic` y vinculando los privilegios del usuario PostgreSQL en cPanel.

### 3. Puesta en Marcha del Backend en Phusion Passenger y Acceso a `/adminetronic`
- **Cargador de arranque (`Backend/loader.cjs`):**
  - Se reforzó la carga explícita de variables de entorno mediante `dotenv.config({ path: path.join(__dirname, ".env") })` antes de importar `index.js`, garantizando lectura consistente independientemente del directorio de trabajo de Passenger.
- **Validación operativa de `/adminetronic`:**
  - Se verificó en producción el inicio de sesión con cookie JWT `HttpOnly`, la protección de rutas administrativas y el flujo de alta/gestión de múltiples cuentas con rol `admin` desde el módulo **`Usuarios y Roles`**.

### 4. Actualización Automática de Producción tras `git commit` + `git push` (CI/CD GitHub Actions → HTTPS 443)
- **Diagnóstico de red y firewall del hosting (`edr.com.mx`):**
  - Se comprobó mediante pruebas de conectividad desde GitHub Actions que el firewall de `mxmexsrv100.edr.com.mx` (`34.125.57.24`) aplica bloqueo geográfico (Geo-IP fuera de México) sobre los puertos administrativos `21` (FTP) y `2083` (cPanel), manteniendo abierto globalmente el puerto `443` (HTTPS).
- **Receptor seguro de despliegue (`Frontend/public/deploy-hook.php`):**
  - Siguiendo el patrón probado en el mismo servidor cPanel, se implementó un endpoint receptor en PHP protegido con comparación en tiempo constante (`hash_equals`) contra el hash `SHA-256` irreversible del secret `DEPLOY_TOKEN` enviado en `X-Deploy-Token`.
  - Restringe estrictamente la escritura al *Document Root* de `etronic.com.mx` (`target: "frontend"`) y a la carpeta `backend_etronic` (`target: "backend"`), bloqueando cualquier escritura sobre `.htaccess`, `.env`, `node_modules`, `data`, `.well-known`, `cgi-bin`, `.user.ini` o `php.ini`.
  - Actualiza y ejecuta `touch` sobre `backend_etronic/tmp/restart.txt` en cada despliegue de Backend para que **Phusion Passenger reinicie automáticamente la aplicación Node.js** sin requerir SSH ni intervención manual.
- **Pipelines en GitHub Actions (`Frontend/.github/workflows/deploy-cpanel.yml` y `Backend/.github/workflows/deploy-cpanel.yml`):**
  - **Frontend:** Se ejecuta en cada `push` a `main` sobre Node.js 24, instala dependencias (`npm ci`), valida formato/linter/tipos con Vite+ (`npm run check`), compila `dist/` (`npm run build`) y publica los archivos codificados en Base64 en lotes de hasta `2.5 MB` (subiendo `index.html` al final) hacia `https://etronic.com.mx/deploy-hook.php`, exigiendo confirmación JSON `{"ok": true}`.
  - **Backend:** Valida la sintaxis de `index.js`, `loader.cjs`, `src/` y `scripts/` con `node --check`, empaqueta los archivos fuente junto con la marca de reinicio `tmp/restart.txt` y los despliega por HTTPS hacia `deploy-hook.php`.

### 5. Normalización de Conexión PostgreSQL y Endpoint de Salud (`Backend/src/db.js` y `Backend/src/app.js`)
- **Compatibilidad IPv4 y limpieza de credenciales en `Backend/src/db.js`:**
  - Se aplicó `.trim()` a `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` y `DATABASE_URL` para prevenir errores por espacios accidentales al capturar variables en la interfaz de cPanel.
  - Se agregó `normalizeHost()` para convertir `localhost` y `::1` en `127.0.0.1` (IPv4), evitando rechazos `code: 28000` en `pg_hba.conf` de PostgreSQL en cPanel bajo Node.js 24.
- **Endpoint de verificación (`Backend/src/app.js`):**
  - Se estandarizó `GET /apietronic/health` (y `/health`) con consulta ligera `SELECT 1` sin exponer metadatos internos sensibles, respondiendo `{"ok": true, "service": "backend_etronic", "dbConnected": true}`.

### 6. Incorporación de Reglas Operativas del Proyecto (`Backend/bitácora/ReglasDeProceso.md`)
- Se registró y adaptó al proyecto **Etronic (`etronic.com.mx`)** el archivo `ReglasDeProceso.md`, estableciendo como reglas obligatorias: no ejecutar `git commit` ni `git push` de forma automática salvo instrucción explícita del usuario, notificar siempre el estado pendiente de Git al finalizar cada ajuste, revisar `ReglasDeProceso.md` al iniciar sesión y mantener actualizada la bitácora diaria.

### 7. Creación de Manual Maestro de Referencia (`Backend/bitácora/Historial_Deploy_cpanel_updateProduct_Github.md`)
- Se documentó de forma íntegra el historial técnico, arquitectura multi-dominio, ajustes obligatorios de código (`loader.cjs`, `db.js`, `app.js`, `axios.js`, `.htaccess`), configuración inicial en cPanel (PostgreSQL, ModSecurity, Phusion Passenger), implementación de CI/CD con GitHub Actions vía HTTPS Puerto 443 (`deploy-hook.php` + `DEPLOY_TOKEN` SHA-256), catálogo de errores resueltos y checklist de 10 pasos reutilizable para acelerar futuros despliegues.

### 8. Enlace al Inicio de Sesión Administrativo en el Logo del Footer (`Frontend/src/pages/LandingPage.jsx`)
- Se envolvió el logotipo de Etronic (`/images/logo-etronic-dark.png`) ubicado en el pie de página (`#main-footer`) con un enlace directo a `/login` configurado con `target="_blank"` y `rel="noopener noreferrer"` para abrir el inicio de sesión de administración en una nueva pestaña.
